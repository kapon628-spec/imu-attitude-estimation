# IMU 姿态估计系统 — 中期总结（Day 1–14）

> 硬件：STM32F411CEU6 + MPU6050 ｜ 工具链：STM32CubeIDE 1.19 + Python
> 时间跨度：Day 1–14（约两周）
> 本文汇总前两周的**系统设计、实测数据、关键技术决策与踩坑**。

---

## 一、项目目标

用最低成本的硬件（约 ¥40），从零实现一套**可解释、可复现、可测量**的六轴 IMU 姿态估计系统：

1. 200 Hz 稳定采样，时间戳由硬件保证
2. 陀螺零偏在线标定
3. 加速度计 + 陀螺仪融合出稳定姿态
4. 实时 3D 可视化与数据曲线
5. **每个结论都有实测数据支撑**，而不是"照教程做出来了"

## 三、关键技术

### 3.1 硬件定时采样 + 微秒时间戳

**问题**：用 `HAL_Delay` 或软件循环，采样周期不可靠。
**方案**：TIM2 中断置标志，主循环处理；TIM5 自由计数做微秒秒表，每帧记录真实 dt。

**实测结果**：

| 指标 | 数值 |
|---|---|
| 采样周期 | 5000 µs |
| 标准差 | **0.00 µs** |
| 最小值 / 最大值 | 5000 / 5000 µs |
| 丢帧率 | **0 / 3001** |
| 有效采样率 | **200.00 Hz** |

> 结论：采样时序由硬件保证，软件处理抖动不会污染积分。

### 3.2 陀螺零偏标定

**原理**：静止时陀螺输出即为零偏，上电后采集 2 秒取平均。

| 轴 | 标定前 (°/s) | 标定后残余 (°/s) | 改善 |
|---|---|---|---|
| gx | −3.802 | +0.057 | 67× |
| gy | −2.389 | −0.094 | 26× |
| gz | −1.252 | +0.053 | 23× |

**另一次标定（Day 13 数据）残余：0.039 / −0.027 / −0.029 °/s**

> **这直接决定了漂移量级**：零偏 3.8 °/s 直接积分 60 秒会漂 228°。

### 3.3 姿态解算：从加速度计到四元数

**加速度计解算倾角**（有绝对参考，但噪声大）：

```c
roll  = atan2f(ay, az)                        // 重力在 Y-Z 平面的投影角
pitch = atan2f(-ax, sqrtf(ay² + az²))         // 分母恒非负 → 限制在 ±90°
```

**互补滤波（Day 10）**：`angle = α(angle + ω·dt) + (1−α)·accel_angle`

**Mahony 四元数滤波（Day 11）**：

```c
// 1. 由当前四元数预测重力方向（体坐标）
v = [2(xz − wy), 2(wx + yz), w² − x² − y² + z²]
// 2. 叉积误差 = 实测重力 × 预测重力
e = a × v
// 3. PI 反馈修正角速度（Ki 项即在线零偏估计）
ω' = ω + Kp·e + Ki·∫e
// 4. 四元数一阶积分 + 归一化
q += 0.5·q ⊗ ω'·dt ;  q /= |q|
```

参数：`Kp = 2.0`（τ = 0.5 s）、`Ki = 0.005`。

### 3.4 三种姿态估计的实测对比（Day 11，静止 60 秒）

| 方法 | roll 漂移 | pitch 漂移 | roll 噪声 σ | pitch 噪声 σ |
|---|---|---|---|---|
| 加速度计 | −0.10° | 0.00° | 0.177° | 0.214° |
| 纯陀螺积分 | **+4.20°** | **−2.40°** | 1.216° | 0.716° |
| **Mahony 四元数** | **+0.20°** | **−0.40°** | **0.067°** | **0.107°** |

**Mahony 同时拿下两个"最好"**：漂移比纯陀螺小 **21× / 6×**，噪声比加速度计小 **2.6× / 2.0×**。

> **稳态误差 = 零偏 / Kp = 0.039 / 2.0 ≈ 0.02°**
> 也就是说：Mahony 把漂移从「线性累积」变成了「有界误差」——这是质的区别。

### 3.5 为什么必须用四元数（Day 12 量化实验）

见 `docs/figs/euler_vs_quat_error.png` 与 `docs/figs/gimbal_sensitivity.png`。

**实验 1：Euler 表示的奇点敏感性**

绕体轴 Y 转 **1.0°**（极小动作），观察 Euler 角变化：

| pitch | Δroll / Δyaw | 放大倍数 1/cos(pitch) |
|---|---|---|
| 0° | 0.34° | 1.0 |
| 80° | 2.17° | 5.8 |
| 88° | 17.88° | 28.7 |
| 89° | 80.00° | 57.3 |
| **89.9°** | **157.84°** | **573** |

**实验 2：大角度三维旋转的积分精度**

ω = (15, 80, 15) °/s，持续 6 s，总转角 497°，真实 pitch 最低 −89.90°：

| 方法 | 最大姿态误差 | 末端误差 |
|---|---|---|
| 朴素 Euler 积分（`roll += p·dt`） | **121.50°** | 72.28° |
| 严格 Euler 运动学（含 1/cos） | 0.75° | 0.73° |
| **四元数积分** | **0.0022°** | ~0° |

> 严格 Euler 运动学姿态误差虽小，但**坐标在奇点处不稳定**（单步 yaw 变化达 72.6°，正常约 0.4°），
> 无法作为融合的状态量。四元数状态始终良态。

## 四、性能评估（Day 13）

### 4.1 长时间漂移率（60 秒静置数据线性拟合）

| 通道 | 方法 | 漂移率 (°/min) | 去趋势残差 σ (°) |
|---|---|---|---|
| roll | 加速度计 | 0.125 | 0.173 |
| roll | 纯陀螺 | **4.196** | 0.104 |
| roll | **Mahony** | **0.202** | **0.032** |
| pitch | 加速度计 | −0.365 | 0.186 |
| pitch | 纯陀螺 | **−2.472** | 0.060 |
| pitch | **Mahony** | **−0.354** | **0.031** |

> 与 Day 11 的 4.20° / 0.20° 完全吻合，交叉验证一致。

### 4.2 噪声水平

| 通道 | 均值 | 去趋势残差 σ | 单位 |
|---|---|---|---|
| 陀螺仪 gx / gy / gz | 0.039 / −0.027 / −0.029 | 0.060 / 0.067 / 0.065 | °/s |
| 加速度计 ax / ay / az | 261.8 / 163.3 / −989.6 | 3.26 / 2.96 / 4.03 | mg |

### 4.3 系统延迟构成

| 环节 | 延迟 | 说明 |
|---|---|---|
| ① 采样周期一半 | 2.5 ms | 平均等待下一个采样点 |
| ② 发送分组 | 0–20 ms | 每 4 帧发一次，平均 10 ms |
| ③ 串口传输 | ≈7.6 ms | 88 字节 @115200 |
| **数据路径合计** | **≈20 ms** | 实测到达间隔 20.00 ms（50.0 Hz） |
| ④ 显示刷新 | 0–100 ms | 面板 10 Hz 时最大 100 ms；30 Hz 时 33 ms |
| **端到端合计** | **约 70 ms（典型）** | 主要被显示刷新拖慢 |

**实测串口到达抖动**：σ = 3.77 ms，最小 1.02 ms，最大 64.71 ms
（PC 侧偶发 60 ms 级停顿，来自 Windows 串口驱动缓冲，非固件问题）

### 4.4 可视化渲染性能

3D 综合面板从初版 **3.4 Hz** 优化到 **30 Hz**（约 10 倍）。优化依据是实测而非猜测：

| 测量项 | 耗时 | 处理 |
|---|---|---|
| 整画布重绘 | 180 ms | 背景缓存 + 局部重绘（blit） |
| **中文文本每帧重绘** | **69 ms** | 中文标签静态化，只更新 ASCII 等宽数字 → 8 ms |
| `auto_ylim` 频繁触发重拍 | — | 每 60 帧才评估 |
| `mplot3d` 3D 轴 | 12–50 ms | **自写正交投影 + Polygon 补丁** → 约 3 ms |

## 五、遇到的典型问题与解决（精选）

| 问题 | 根因 | 解决 |
|---|---|---|
| 采样周期变成 502 ms | 主循环有 `HAL_Delay(500)` 阻塞 | 改用计数器分频控制低频动作 |
| dt 恒为 0 或乱跳 | 用 TIM2 计数器当时间戳，而它每 5 ms 归零 | 增加 TIM5 自由计数器 |
| dt 放大 96 倍 | TIM5 预分频未设置（跑在 96 MHz） | Prescaler = 95 |
| I2C 全 0 / 唤醒失败 | 上电未稳定就首次写入 | `HAL_Delay(100)` + 5 次重试 + 回读校验 |
| roll 在 ±180 疯狂跳变 | ① 数值环绕（显示问题）② pitch=±90 死锁（真问题） | ① `np.unwrap` / 相对值显示 ② 改四元数 |
| 编译 21 个 `multiple definition` | 备份 `.c` 放在 `Core/Src/` 被自动编译 | 改名 `.c.bak` |
| 面板数字/曲线重影 | 拍背景缓存时未隐藏动态元素 | 保存背景前 `set_visible(False)` |
| 3D 立方体不显示（两次） | ① `mplot3d` 隐藏后不重算投影 ② `ax3.draw()` 在 TkAgg 下不生效 | 自写 2D 投影 + 统一用 `draw_artist()` |
| 离线时间轴少算 4 倍 | `dt` 是采样周期，但每 4 帧才发一次 | 重建时间轴时乘 4 |

> **最值得记的一条方法论**：验证 GUI 渲染必须在**真实后端**上做，并检查**真正上屏的那份缓冲**；
> 用 Agg + `savefig()` 会掩盖 blit 路径的问题（本项目因此连续两次误判"已修好"）。

## 九、结论

1. **采样与时间戳**：硬件定时 + 微秒时间戳，实测 200.00 Hz、丢帧率 0、dt 标准差 0。
2. **算法选型有据可依**：Mahony 相比纯陀螺漂移降 21×，相比加速度计噪声降 2.6×；
   四元数相比朴素 Euler 积分在 497° 旋转下误差从 **121.5° 降到 0.0022°**。
3. **可视化可用**：3D 面板 30 Hz，且渲染性能优化过程有完整测量记录。
4. **已知边界清晰**：yaw 缺绝对参考、陀螺量程限制、显示刷新延迟，均已量化并列入后续计划。

> 这套系统的价值不在"用了什么高级算法"，而在于**每个设计决策都有可复现的实测数据支撑**。
